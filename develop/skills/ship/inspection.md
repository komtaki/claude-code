# 検品リスト

成果物を受け取るときに、その種類に当てはまる節の項目をタスクリストに写し、項目ごとに根拠（開いたファイルと行、実行したコマンドと出力）を残してから完了にする。根拠を残せない項目は完了にしない。「規約と照らす」だけでは、見るべき箇所を飛ばしても気づけないため、成果物の種類ごとに見る箇所を決めておく。

## A. 実装（`code`）

「2. 実装」で、サブエージェントの成果物を受け取るとき。

- 依頼の要件を 1 つずつ挙げ、それぞれを差分の箇所とテストに対応付ける。どの要件にも対応しない差分は、サブエージェントの報告か commit メッセージで入れた理由を確かめ、引用を残す。
- 足したテストを base の実装で走らせる。挙動を変える差分では落ちることを確かめる（base でも通るテストは変更を守っていない）。挙動を保つ差分では通ることを確かめる。
- 作業先の規約を開き、差分の該当箇所と 1 つずつ照らす。
- サブエージェントが回していない検証を 1 つ回す（実際に起動する、テストにない入力で動かすなど）。
- タスクごとのレビュー（最後はブランチ全体のレビュー）で出た Critical・Important が直っていることを、指摘の箇所を開いて確かめる。

## B. 共通部の変更（`shared`）

A に加えて見る。

- 参照元を grep で全数挙げ、依頼の対象と対象外に分けた表を作る。grep のコマンドと件数を残す。
- 対象外の参照元の挙動が変わらない根拠を示す（既定値のままで通るテスト、opt-in の引数を渡していないことなど）。変わるなら止めて聞く。

## C. 不具合の修正

A に加えて見る。

- 修正前に再現させた手順と出力。
- 原因を示す一次情報（ログ・コードの行・データ）。
- 修正後に、同じ手順で再現しなくなった出力。

## D. ドキュメント（`docs`）

メインエージェントが書いた文書を、「3. simplify と AI レビュー」に進める前に。

- 作業先の規約を開き、差分の該当箇所と 1 つずつ照らす。
- 変えた事実を grep し、別の文書で同じ事実を繰り返していないか、古いまま残っていないかを確かめる。
- コードや設定に依る主張は、出典を開いて主張どおりか確かめる。

## E. AI レビューの指摘

「3. simplify と AI レビュー」で指摘を受け取るとき。

- 指摘ごとに該当行を開き、事実か確かめる。事実でないと判断した指摘は、否定する一次情報を残す。
- `error` は採用・不採用と理由を残す。`info`・`warn` は事実確認の結果を添えて lensdiff に流し、採否は lensdiff で人が決める。作業先が lensdiff を行わない場合は自分で採否と理由を残し、作業先が不採用の理由を PR 本文に残すと決めていれば、「5. PR」で pr-writer に渡す。
- 直した後に関係するテストか検証を回し直し、意図した挙動が保たれていることを確かめる。

## F. lensdiff の資料

「4. lensdiff レビュー」で `develop:code-describe` の資料を受け取るとき。

- 解説の行番号を最新の差分と照らす。修正で差分が変わった後は取り直す。
- 出典のファイルと行を開き、実在して主張どおりか確かめる。
- `shared` なら、「対象外の参照元への影響」の節の件数と根拠が、B の grep の件数・根拠と一致することを確かめる。

## G. PR 本文

「5. PR」で pr-writer が作った PR、または書き直した PR を `gh pr view` で読むとき。

- 本文の主張を 1 つずつ、差分か渡した経緯に照らす。どちらにもない主張は直させる。
- 渡した経緯（未マージの依存、既定で決めたこと、不採用の指摘）が落ちていないことを確かめる。
- `overview.md`・`explanations.json` の文と PR 本文を突き合わせ、同じ文を写していないことを確かめる。
- タイトルを差分の主な変更（変えたファイルと満たした要件）と照らす。

## H. CI の修正と bot レビューへの対応

「5. PR」で CI の失敗や bot の指摘を直したとき。`ccd_pr` の auto-fix による修正も含む。

- 失敗ログの原因行と、修正の箇所を対応付ける。
- 修正後の CI の結果（`gh pr checks` の出力）を残す。
- bot の指摘ごとに、対応したか、しない理由を残す。対応したスレッドが resolve されたことを、`develop:pr-review-fix` の「コメントの resolve」のクエリで `isResolved` を見て確かめる。
