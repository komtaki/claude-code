# PR 作成手順

日本語でのコミュニケーションを基本とする。

## commit

commit のフォーマット・粒度・Type は **commit スキル**に従う。

## 作成手順

1. 現在のブランチとコミット状況を確認する
2. デフォルトブランチにいる場合は、fetchして最新にする。そのあと差分から名前を決めて新しくブランチを作成する。
3. **`simplify` スキルで差分（base ブランチとの差分全体）をセルフレビューする。** 指摘があれば適用し、追加の commit として積む（commit スキルの粒度・フォーマットに従う）。既に一部が push 済みでも、この時点で改めて実行し、指摘の修正を次の push に含める。
4. ブランチを作成したら、ブランチを remote に push (git push)
5. **複雑な実装の場合は、`develop:code-reference` スキルで資料を作る。** 該当するかの判断基準は同スキルの1章にある。作った資料のリンクは PR 本文に載せる
6. **タイトル・本文は `Agent` ツールで `develop:pr-writer` を起動して書かせる。** ブランチ、ベースブランチ、差分から読み取れない経緯（事実のみ）を渡す
7. 書き出されたファイルを読んで検品する。直させる場合は、経緯に判断を足して書き直させる
8. **PR をドラフト状態で作成する** (`gh pr create --draft --title "..." --body-file <パス>`)
   - Assign は komtaki を指定する
9. CIの成功をサブエージェントで待機して、確認。CIが失敗したら修正する
