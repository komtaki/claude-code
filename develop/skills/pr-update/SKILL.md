# PR 本文更新手順

## 更新手順

1. **タイトル・本文はサブエージェントに新規に書かせる。** 自分で下書きしてから清書させると、手元の文章を捨てられず、**create スキル**の「提出前セルフチェック」が適用されないまま通る。下のプロンプト雛形をそのまま使い、`Agent` ツールで `general-purpose` を1つ起動する
2. 書き出されたファイルを読んで検品する。直させる場合は、雛形の「経緯」に判断を足して書き直させる
3. タイトルと本文をまとめて反映する (`gh pr edit --title "..." --body-file <パス>`)
   - 本文はファイルで渡すため、**create スキル**の「PR本文のエスケープについて」は適用しない

## プロンプト雛形

経緯には事実だけを並べる。完成した文章や言い回しを渡すと、下書きを清書させるのと変わらなくなる。

````
次の PR のタイトルと本文を新規に書いてください。既存の本文は現状確認のための材料であって、下敷きにはしないでください。

PR 番号: <番号。省略時は現在のブランチから解決される>
ベースブランチ: <base-branch>

差分から読み取れない経緯（事実のみ）:
- <一次情報の URL / チケット番号 / ユーザーが下した判断 など>

材料は自分で集めてください。

- `gh pr view --json title,body`
- `git diff <base-branch>...HEAD`

執筆基準は `develop:pr-create` スキルの「PR の本文の重要な注意事項」と「提出前セルフチェック」に従ってください。

`gh pr edit` は実行しないでください。書き上げたタイトルと本文を `$TMPDIR` 配下のファイルに書き出し、そのパスを報告して終わってください。
````
