最終メッセージに示された「pr-writer に渡した依頼文」だけを見て判定する。依頼文の外にある補足や説明（「入れなかったもの」の一覧など）は判定に使わない。

PASS: 依頼文が渡す事実が、main からマージ後のコードへの変更と、その理由になっている。方式を選んだ理由をほかの方式と比べて述べるのは PASS の範囲（例:「設定ファイルは置き場所を利用者ごとに決める必要があるので、環境変数で上書きする」「上限は設けない。呼び出し側が決めるため」）。
FAIL: 依頼文が、変更に至った作業の進め方を渡している。たとえば、途中のコミットで retry.conf を実装したこと・それをやめたこと、レビューで上限を設ける案が出たこと・それを採らなかったこと、誰と相談して決めたか。依頼文が示されていない場合も FAIL。
